# Управление привязками из номенклатуры 1С

В `/admin/onec-items` менеджер открывает «Привязать», «Изменить привязку» или «Характеристики и привязки» в строке товара. Поиск находит существующие карточки по названию, нашему и поставщицкому артикулу. Выбранная карточка показывается с фото и ссылкой для проверки. Очистка выбора и сохранение снимают связь; новую карточку форма не создаёт.

## Данные и защита

- Единственный реестр связей — `integration_products` источника `onec`. Раздел сопоставления использует те же записи. Поля в `onec_items` — производное отображение, обновляемое сразу после изменения реестра.
- Идентификатор исполнения сохраняется полностью: `GUID товара#GUID характеристики`. Нулевая характеристика и голый GUID считаются одной логической позицией; имеющиеся записи-алиасы согласуются одним выбором без удаления ценовых строк.
- Родитель с характеристиками не получает карточку произвольного цвета. В таблице показано количество привязанных исполнений, а в форме — каждое отдельно. Общая привязка родителя при наличии характеристик требует явного снятия, прежде чем назначать исполнения.
- Одну карточку нельзя назначить двум разным характеристикам в этой форме. Конфликт, возникший из другого интерфейса, помечается в номенклатуре, а не разрешается случайным порядком строк.
- Блокировка строки номенклатуры и строк реестра, проверка исходного снимка, проверка полного состава исполнений и транзакция защищают от параллельного перезаписывания и частичных сохранений.
- Действие доступно только менеджерам/администраторам. Группы, помеченные на удаление товары, удалённые и архивные карточки назначать нельзя.
- Снятая связь остаётся записью со статусом `ignored`, чтобы очередной импорт автоматически не восстановил её. Повторная ручная привязка разрешена.
- История в `onec_item_link_changes` содержит полный внешний ID, старую и новую карточки, пользователя и время. Старые решения до включения истории не выдумываются.
- Цены, остатки, заказы, заявки и корзины не перезаписываются. API-вызовов в 1С при работе с привязками нет. Поиск ограничен 30 результатами; нет фонового опроса страницы.
- Ручная привязка характеристики не обучает общую связь по артикулу, который может быть одинаков у нескольких цветов. Действие создания/привязки из карточки не забирает первую попавшуюся характеристику вместо всего товара.

## Разовое обновление после публикации

`php artisan onec:refresh-links` пересчитывает только отображение по уже существующему реестру, без запросов в 1С, изменения самих привязок, создания карточек или изменения цен/остатков. Применить после миграции, чтобы убрать старое неверное отображение характеристик и показать недавно подтверждённые связи.

Новые характеристики доступны, когда они поступили в существующий обмен. Форма не придумывает исполнения и не создаёт их в 1С.

## Проверки

- SQLite: `OneCCatalogLinksTest`, `OneCNomenclatureTest`, `OneCItemCreateTest` — 21 проверка, 181 assertions.
- Изолированная MySQL 8: те же затронутые сценарии до дополнительной проверки отображения внешнего конфликта — 20 проверок, 179 assertions. Временная база удалена после завершения.
- Проверка формы через Livewire включает сохранение реальным действием таблицы. Полный набор тестов не запускался.
