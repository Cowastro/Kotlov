# ВАМ Экспресс: чтение заявок

Раздел: `/admin/vam-express-shipments`, группа «Доставки».
Администратор сохраняет логин/пароль в «Настройках входа» и включает чтение.
Пароль не возвращается в форму; настройки шифруются APP_KEY и находятся на private/local disk.
Смена аккаунта после импорта запрещена, чтобы не смешивать чужие отправления.

`shipping:sync-vamexpress` вызывается планировщиком каждую минуту, но выполняет обмен
раз в 30 минут либо после ручного запроса (минимальная пауза между попытками — 2 минуты).
За запуск читаются до 4 страниц / 100 свежих заявок, затем до 10 ID из очереди поиска
и ранее привязанных заявок суммарно. Старые привязанные заявки обновляются по очереди.
Загрузка всей истории автоматически не запускается. Между HTTP-запросами — 1,25 секунды,
автоматических повторов HTTP нет; параллельные запуски блокируются.

Полный 32-символьный ID из ссылки TicketEdit — уникальный ключ; 7-символьный ID
используется только для отображения и поиска. По совпадению города/цены заказ не привязывается.
Менеджер выбирает заказ вручную. Импорт не меняет order_id, цены, оплату, подтверждения
или статус заказа KOTLOV. Исчезновение строки из ответа не удаляет локальную заявку
и не означает отмену/доставку. Некорректный ответ отклоняет всю текущую загрузку.

Адаптер использует только GET входа/списка и POST входа/поиска/пагинации TicketView.
Создание, сохранение и удаление заявок у перевозчика не реализованы.

## Этикетки существующих заявок

В строке заявки доступна «Этикетка»: А4 или лента 78 мм. В привязанном заказе
есть «Этикетки ВАМ» со списком уже связанных отправлений. Для ленты нужно
выбрать в драйвере принтера бумагу 78 мм и масштаб 100%; высоту задаёт принтер.

Загрузка авторизуется, ищет заявку по короткому ID, проверяет полный ID ссылки
и выбирает только checkbox нужной строки. POST выполняется только на TicketView
с btnPrintVinil или btnPrintVinilForVinilPrinter. Следующая страница — штатный
макет перевозчика. ID в thisPrint сверяется с выбранной заявкой; чужая этикетка
не отображается. Скрипты/обработчики/внешние ресурсы не переносятся на наш домен.
Неизвестная структура (включая новые изображения штрихкодов) блокирует печать
до адаптации вместо потери части этикетки. Адреса/получатель берутся из формы ВАМ.

Макет хранится 15 минут в зашифрованном cache, разделённом по аккаунту, полному ID
и формату; печать повторной копии не вызывает новых запросов к перевозчику.
Применяются общая с синхронизацией блокировка, лимит 6 новых загрузок в минуту
и пауза 2 минуты после ошибки. Страницы печати закрыты от клиентов и кеширования
браузером/прокси. Компоненты заказа, его суммы и статус печать не меняет.
Внешние адреса фиксированы, HTTPS обязателен; cookies живут только в памяти одного запуска.
HTML, cookies и данные входа не записываются в журнал. При изменении HTML адаптер
останавливает загрузку и показывает сообщение, не повреждая сохранённые данные.

Перед первой рабочей синхронизацией нужен вход, сохранённый администратором в настройках.
Проверить количество импортированных строк, статусы и привязку на существующем заказе.
Точечная проверка: `php artisan test --filter=VamExpressSyncTest`.

## Профили и фильтры

Профиль отправителя берётся из readonly-поля tbUserProfile при GET существующей
TicketEdit.aspx?id=полный_ID, не выводится из груза, города или связанного заказа.
Профиль хранится отдельно в sender_profile. Обновление списка не стирает его.
Обычный обмен дополнительно читает до 10 непроверенных/устаревших профилей;
между запросами карточек выдерживается 2,5 секунды, повторная проверка — через сутки.
Первичное ограниченное заполнение: `shipping:sync-vamexpress-profiles --limit=100`.
Команда использует общую блокировку с обменом и этикетками, не отправляет формы
редактирования и сохраняет каждый подтверждённый профиль отдельно.

Быстрые вкладки применяются вместе с поиском и фильтрами профиля, точного статуса
и связи с заказом. «Доставлены» включает Доставлена/Завершено, но не Обработана/Оплачено.
Цвет и значок дополняют точное название статуса перевозчика; неизвестные статусы серые.

## Черновик и предварительный расчёт

`/admin/vam-express-calculator` — быстрый расчёт без заказа; результат можно сохранить
в `/admin/vam-express-drafts`. В заказе «Черновик ВАМ» создаёт один текущий черновик
под блокировкой заказа либо открывает существующий. Суммы/статус заказа не меняются.
Сохранение допускает неполные данные. Payload и снимок расчёта зашифрованы, версия
защищает от перезаписи другой вкладкой; смена ценовых параметров сбрасывает расчёт.
Повторное сохранение одного быстрого подбора идемпотентно по ключу страницы и данным.

Изучены карточки трёх используемых профилей и многопозиционная заявка, валидаторы
формы TicketEdit и штатные AJAX-функции. Подтверждены справочники 5 профилей и
280 тарифных категорий. Встроенные ключи сервисов читаются из текущей формы, не
зашиты в код, не передаются браузеру и хранятся только в зашифрованном кеше.

Калькулятор кабинета вызывает POST `/WebServices/UserAPI/CalculatorAPI.asmx/Calculate`.
Тело jsonString: city_id, profile_type (первый символ идентификатора профиля),
user_discount/user_id из аккаунта, goods с точными description и number,
express_cost из настроек аккаунта; для типа 3 также assessed_cost.
Поиск города — документированный POST GetCityForAutocompliteJSON с query/appkey,
профили — GetAvaliableuserProfilesForUserJson с query/appkey/id.
Каждая категория выбирается из справочника; комплект 10–15 шт. с number=1
не превращается автоматически в 15 тарифных единиц. Оценка считается за единицу.
На существующем примере «Дымоход 10–15 шт.» → Кобрин сервис вернул 44.9999;
нормализованная денежная сумма 45.00 совпала с тарифом сохранённой заявки.
Ответы OutOfTitles, DeviationIsUnknown и другие ошибки не преобразуются в ноль.
Стоимость предварительная: дополнительные услуги/забор/подъём не придумываются.

| Поле черновика | Поле кабинета / правило |
| --- | --- |
| Профиль | tbUserProfile / hfUserProfileID, только профили аккаунта |
| Категория, марка/модель, оценка, число единиц | tbGoodsDescriptionN, tbGoodsModelN (50 символов), tbGoodsCostN, tbGoodsNumberN |
| Коробки | tbBoxesNumber, отдельно от количества товаров |
| Фамилия | tbRecipientFirstName (название в кабинете исторически обратное) |
| Имя | tbRecipientLastName |
| Отчество | tbRecipientThirdName; 2–30 символов без цифр/пробелов |
| Телефоны | tbRecipientPhone / tbRecipientPhone2; основной нормализуется в +375… |
| Город/район | tbCity / hfCityID, точный пункт из справочника |
| Улица, дом, корпус, квартира | ddlRecipientStreetPrefix / tbRecipientStreet / tbRecipientStreetNumber / tbRecipientKorpus / tbRecipientKvartira |
| Точка отправления | tbSenderCity / hfSenderCityID, ddlSenderStreetPrefix, tbSenderStreetName/Number/Housing/ApartmentNumber |
| Дата | tbDeliveryDate; дата отправки позже сегодняшней по времени перевозчика |
| ТТН | tbTtnSeria / tbTtnNumber; типы профиля 2/3 требуют 2 буквы и 7 цифр |
| Документы и примечания | tbOtherDocuments / tbNote |
| Паспорт | В проверенных заявках юрпрофилей пуст; в этот этап не собирается |

ФИО и адрес заказа не разбиваются догадкой: исходные строки сохранены отдельно,
а менеджер подтверждает структурированные поля. ТТН из старых примеров не копируются.
Поля расчёта не включают ФИО/телефоны/улицу получателя. Поиск и расчёт кешируются,
ограничены частотой и общей блокировкой с обменом/этикетками. Внешние вызовы
сохранения TicketEdit, отправки письма и создания заявки отсутствуют.

Точечная проверка: `php artisan test --filter=VamExpressDraftsTest`.
