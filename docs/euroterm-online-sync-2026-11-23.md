# Евротерм: обновление онлайн-прайса

Ранее `supplier:sync-euroterm` без аргумента повторно импортировал статический снимок от 20.10.2026. Теперь без файла он входит в https://euroterm.by/prajs-list.html и последовательно читает все страницы. Явно заданные XLSX/JSON по-прежнему поддерживаются.

## Где ввести доступ

Администратор: **Центр синхронизаций → Вход Евротерм**. Эта же кнопка есть в карточке поставщика Евротерм. Ввести логин и пароль от euroterm.by, нажать **Сохранить и обновить**. Сохранение запрашивает фоновый запуск в течение пяти минут. Далее обновление выполняется каждые восемь часов.

Пароль никогда не подставляется обратно в форму. Пустое поле при повторном сохранении оставляет прежний пароль. Учётные данные зашифрованы ключом приложения в приватном хранилище `suppliers/euroterm/credentials.enc`; публичного URL или журнального вывода секретов нет. Форму и её действие может использовать только администратор.

## Как обновляются данные

- Подтверждение входа требуется на каждой странице. Гостевые цены и истёкшая сессия не принимаются.
- Закупка читается из цены аккаунта, розница — из отдельного поля и явно указанного коэффициента на сайте поставщика.
- Из статуса «В наличии» не выводится числовой остаток. Количество остаётся `null`; только явное «Нет в наличии» даёт ноль.
- Обновляются исключительно уже существующие предложения этого поставщика по нормализованному артикулу. Карточки, привязки по похожему имени и новые предложения автоматически не создаются.
- Существующая ссылка на товар сохраняется. Розница меняется только у карточек, основным поставщиком которых является Евротерм.
- Исчезнувшие из онлайн-прайса строки не обнуляются. Их прежний срок обновления остаётся прежним.
- Категории, бренд и единица из существующего предложения сохраняются, если онлайн-прайс их не передаёт.

## Ограничения нагрузки и защита

Один процесс, не менее одной секунды между страницами, максимум 160 страниц и десять минут загрузки. Вся загрузка завершается до записи в БД; частичный сетевой сбой или потеря входа останавливает обновление. Повтор целой страницы отдельно фиксируется, её ссылки также обходятся, а данные проверяются по артикулам. Неизменившийся повтор карточки учитывается один раз. Разные карточки/цены с одинаковым артикулом исключаются целиком как неоднозначные; остальные корректные строки обновляются. Строки без артикула или обеих цен также исключаются без подстановок. Проверенный снимок с отдельными списками исключений и повторённых страниц хранится приватно в `suppliers/euroterm/latest-online.json`. Отсутствие товара среди полученных строк не считается доказательством нулевого остатка.

Старый снимок не используется как неявная замена свежему источнику. Пока идёт загрузка, соединение MySQL освобождается только вне активной транзакции. Разрывать соединение внутри транзакции нельзя: это откатывает её данные (в частности, подготовленные данные MySQL-теста).

Попытка входа записывается до запроса к поставщику. При ошибке нет повторных попыток каждые пять минут: следующий автоматический запуск через восемь часов либо после явного повторного сохранения настроек администратором. Одна синхронизация защищена блокировкой от наложения.

Результаты и изменения доступны в центре синхронизаций. Журнал ограничен данными Евротерма, без обхода всех поставщиков.

Проверки: авторизация, обе цены, неизвестное количество, полнота загрузки, отказ при частичном сбое, шифрование и доступ администратора, повторное обновление без дублей, сохранение чужой розницы и отсутствующих позиций. Полный набор тестов не запускался.
