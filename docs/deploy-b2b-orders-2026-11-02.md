# Деплой отдельного модуля B2B-заказов

## Порядок выпуска

1. Развернуть код без запуска команды переноса старых заказов.
2. Выполнить миграции:

   ```bash
   php artisan migrate --force
   ```

3. Проверить план переноса старых B2B-заказов (команда ничего не изменяет):

   ```bash
   php artisan b2b:orders:migrate-legacy
   ```

4. Сверить число найденных записей с прежней B2B-выборкой и выполнить перенос:

   ```bash
   php artisan b2b:orders:migrate-legacy --apply
   ```

5. Повторно запустить preview. Команда идемпотентна: уже перенесённые записи не
   дублируются. Старые строки `orders` не удаляются и остаются для аудита, но
   скрываются из розничной CRM-очереди после появления связи `legacy_order_id`.
6. В карточках нужных сотрудников включить «Доступ к B2B-заказам» и назначить
   ответственного B2B-менеджера в карточке партнёра.
7. Проверить контрольный заказ: кабинет → отдельная очередь B2B → проверка всех
   строк → условия партнёру → подтверждение партнёром → счёт в кабинете и email →
   оплата либо отгрузка по кредитному лимиту.

## Склады, остатки и резерв

Позиция B2B-заказа привязана к одному складу (`b2b_order_items.stock_key`):
`integration:{id}` — 1С и партнёрские фиды, `warehouse:{id}` — импортированные
остатки складов (`product_warehouse_stocks`), `supplier:{id}` — прайс поставщика.
Новых источников остатков нет: используются те же синхронизации, что и сейчас.

- При оформлении заказа и при «Принять в работу» система сама проверяет каждую
  позицию: хватает свободного остатка — «Подтверждено» и резерв; на
  привязанном складе пусто, а на другом есть — позиция переносится туда; хватает
  части — «Частично»; остаток не передаётся — «Не проверено» с подсказкой
  «Подтвердить у поставщика».
- Менеджер решает только жёлтые строки: выбрать склад, подтвердить или убрать
  позицию с причиной. Решение менеджера повторная проверка не перезаписывает.
- Свободный остаток = остаток источника минус активные резервы других B2B-заказов
  (`b2b_order_reservations`). B2B-каталог показывает партнёрам уже свободный
  остаток.
- Отмена снимает резерв (`released`), отгрузка списывает его (`shipped`), дальше
  остаток обновит очередная синхронизация.
- Розничный сайт B2B-резервы пока не вычитает. Передача резервов и
  заказов `B2B_ORDER` в 1С — следующий этап.

## Быстрая проверка после выпуска

```bash
php artisan route:list --path=admin/b2b-orders
php artisan route:list --path=b2b/cabinet/b2b-orders
```

- обычный менеджер без флага получает 403 на `/admin/b2b-orders`;
- B2B-менеджер видит новую очередь и карточку заказа;
- новый B2B checkout не создаёт строку в `orders`;
- розничный заказ продолжает создаваться в `orders`;
- счёт нельзя выставить до проверки всех строк и подтверждения партнёром;
- в карточке заказа вкладка «Товары и склады»: у каждой строки виден склад,
  свободный остаток, резерв, закупка и маржа; кнопка «Проверить наличие»;
- отсрочку нельзя активировать до выставления счёта.

## Откат

До переноса данных можно откатить последнюю миграцию обычной командой Laravel.
После `--apply` сначала сохранить выгрузку таблиц `b2b_orders*`. Исходные
розничные записи не удаляются, поэтому при необходимости старый экран можно
временно вернуть кодовым откатом без потери исторических заказов.
