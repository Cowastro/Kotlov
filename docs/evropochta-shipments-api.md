# Европочта: управление отправлениями

Единый раздел: `/admin/evropochta-shipments`, меню «Управление» у заказа.

## Оплата

Для неоплаченного заказа наложенный платёж равен `max(0, товары − скидка) + доставка` — ровно один итог заказа. При оформлении неоплаченный заказ получает способ оплаты `evropochta_cod`. Для уже оплаченного заказа наложенный платёж не создаётся. Стоимость доставки уже включена в итог; второй раз к наложенному платежу она не прибавляется.

`shipment_payer = 0`, `cash_on_delivery_payer = 0`: услуги перевозчика и комиссия — за счёт отправителя. Менеджер не может подменить плательщика через данные формы. Суммы и плательщики сохраняются вместе с конкретным треком. Просмотренная сумма защищена подписью: изменение денег, способа оплаты или параметров посылки требует повторного просмотра формы.

## Используемые операции API

База: `https://api-kassa.evropochta.by/api/external`. Заголовок авторизации `Token` берётся из настроек сервера и не выводится в интерфейс или журналы.

| Операция | Запрос |
| --- | --- |
| Отделения | GET `stores` (кэш 6 часов) |
| Расчёт | POST `postal/payment/calculate` |
| Оформление | POST `postal/create` |
| Состояние | GET `postal/{number}` |
| История | GET `postal/history?number=...` |
| Ярлыки | GET `label/{thermal\|address}/{number}` |
| Сумма и плательщики | PATCH `postal/{number}`: `payment_amount`, `shipment_payer`, `cash_on_delivery_payer` |
| Отмена | POST `postal/{number}/cancel` |

PATCH существующего трека проверен на реальной заявке; ожидаемый ответ — `200` и сообщение «Внесены изменения в заявку». Перед PATCH и отменой заново читается статус: допустим только код `0` («Заявка создана»). Отмена отправления не отменяет заказ KOTLOV.

GET состояния не возвращает сумму наложенного платежа и плательщиков. Поэтому старые отправления без сохранённого снимка показывают «По заказу · проверьте сумму в заявке», а не неподтверждённую сумму перевозчика. После подтверждённого PATCH источник обозначен «Установлено через API Европочты».

## Защиты

- Управление доступно только активным сотрудникам с правами на заказ; изменения закрытых заказов запрещены.
- Общая блокировка конкретного трека исключает одновременные операции интерфейса и фоновой проверки.
- Ручная проверка статуса — не чаще раза в 3 минуты. Открытие таблицы, меню и фильтров не обращается к API.
- Фоновая синхронизация сохраняет прежний лимит: до пяти отправлений за запуск, не чаще раза в 30 минут для каждого.
- Ошибка API не сохраняется как успешное изменение. Создание ярлыка не считается передачей посылки перевозчику.

## Рабочий список и архив

По умолчанию открыта вкладка «В работе». Отменённые, завершённые и архивные заказы, а также подтверждённо отменённые заявки перевозчика, доступны в «Завершённые / отменённые» и «Все». Дополнительные фильтры скрыты под кнопкой фильтров.

Архивный трек без сохранённого статуса получает одну фоновую проверку с прежним лимитом запросов. Сохраняются только сведения перевозчика: заказ не открывается заново, старые письма и СМС не отправляются. Уже проверенные закрытые треки и подтверждённо отменённые заявки больше не опрашиваются постоянно.
